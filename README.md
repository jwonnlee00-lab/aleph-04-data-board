# 오늘의 진짜 정보판 — 데이터가 안 올 때

과제 4. 공개 원천의 JPY/KRW 일별 기준환율을 실제로 수집하고, 실패 시 마지막 정상값과 일별 기록을 보존합니다.

- 결과물: https://honest-daily-board-krw-20261014.jwonnlee00.chatgpt.site
- 소스: https://github.com/jwonnlee00-lab/aleph-04-data-board
- 공개 원천: https://api.frankfurter.dev/v2/providers/ecb/rate/JPY/KRW
- 원천 설명: https://frankfurter.dev/

## 짧은 확인 방법 4줄

어디로 가나요: 공개 화면의 ‘카드 5 / 보존한 실제 이틀’과 ‘카드 3 / 공개 합성 시험’으로 갑니다.

무엇을 하나요: ① 실제 이틀의 표와 변화식을 확인 ② 실패 종류를 선택해 재생(5종 반복) ③ ‘다시 시도 · T04-RECOVER-D2’를 누릅니다.

무엇이 보이면 통과인가요: 실제 KST 10/14·10/15의 848.35원·843.64원과 차이 -4.71원이 일치하고, 실패 후 105 pt·stale를 보존하며 재시도 후 120 pt·fresh/none·총 2행이 보입니다.

안 될 때 무엇이 보이나요: 실패별 설명·오래된 값 표시·다음 행동이 보입니다. 정상값이 없으면 ‘—’, 날짜가 부족하면 비교 대기, 보존본 조회가 실패하면 확인 실패 안내가 나옵니다.

## AI와 나의 판단 3줄

AI에게 맡긴 일: 공개 원천 연결, 화면과 저장 로직 구현, 합성 실패·복구·날짜 경계 시험, 실제 이틀 기록 대조와 변화 재계산을 맡겼습니다.

직접 판단한 일: 기록할 값을 엔화로 선택했고 안내카드 순서대로 진행하도록 정했으며 시크릿 창에서 공개 접근을 확인했습니다.

AI 제안을 따르지 않은 일: 처음 AI가 정한 달러 환율 주제를 따르지 않고 제가 선택한 엔화로 변경했습니다.


## 실제 기록과 완료 조건

`dist/observations.json`이 모든 기기에서 볼 수 있는 공유 기록입니다. `kstDate`는 실제 요청 시각의 한국 날짜, `value.date`는 원천의 기준일입니다. 과거 원천값을 조회하더라도 실제 수집일을 소급하지 않습니다. 같은 signal_id + KST 날짜의 성공 조회는 기존 행을 최신 정상값으로 갱신하며 record ID와 최초 조회 시각을 유지합니다. 최초 대조 자료는 firstObservation으로 별도 보존합니다. 원천 값이 같으면 변화값 0도 유효합니다.

2026-10-14와 2026-10-15의 서로 다른 실제 KST 날짜 기록을 보존했습니다. 카드 5 고정본의 값은 848.35원/100엔과 843.64원/100엔이며 변화는 -4.71원(-0.56%)입니다. 원자료·조회 시각은 그대로 보존하며 정규화 값은 소수 둘째 자리로 반올림합니다. 자세한 대조와 원천 시각·플랫폼 영수증의 한계는 evidence/card-5.md를 확인하세요. 작업시간 6~7시간을 실제로 사용했다고 주장하지 않습니다.

GitHub Actions가 매일 07:15 UTC / 16:15 KST에 조회를 시도합니다. 예약 실행은 GitHub 사정으로 늦거나 누락될 수 있습니다. 저장소 Actions의 `Collect real daily observation`에서 `Run workflow`로 실제 수집을 실행할 수도 있습니다. 이 작업은 비밀 키를 요구하지 않고, GitHub가 제공하는 저장소 범위의 `GITHUB_TOKEN`을 사용합니다. 수집 실패 상태도 커밋하며 정상 기록은 지우지 않습니다.

공개 사이트는 방문할 때 GitHub `main`의 공유 기록을 읽습니다. GitHub 조회에 실패하면 배포에 포함된 보존본과 보존본 안내를 표시합니다. 방문 중 실제 API 조회는 이 기기의 마지막 정상값만 갱신합니다. 브라우저 저장소의 값은 날짜 2건 증거로 세지 않습니다. 예약 수집이 저장한 새 공유 기록은 화면 새로고침으로 반영됩니다.

## 실패 정책

카드 3의 공개 패키지에 맞춰 timeout, auth(401/403), rate_limit(429), offline, schema_error를 합성 재생합니다. 정상 D1-A→D1-B와 RECOVER-D2는 공통 상태 저장 함수를 사용하며, 실패에는 마지막 정상값 보존·stale 표시·다시 시도가 있습니다. 합성 시계와 실제 기록은 분리됩니다. 자세한 결과는 evidence/card-3.md를 확인하세요.

기준일이 오늘보다 앞서면 ‘이전 기준일’로 안내합니다. 5일을 넘긴 응답은 거부합니다. 이 5일은 프로젝트의 보수적인 정책이며 ECB의 공식 장애 기준이 아닙니다. 어제 대비는 KST 오늘과 정확히 어제의 최신 정상 기록이 모두 있을 때만 계산합니다. 하루가 비면 그보다 오래된 기록을 어제로 취급하지 않습니다.

## 개발 및 검증

Node.js 22 이상. 외부 패키지 설치가 필요 없습니다.

```sh
npm test
npm run collect
npm run preview
```

로컬 미리보기는 http://127.0.0.1:4173 입니다. `npm run collect`는 실행 당시 날짜로 실제 API에 요청합니다. 실패하면 정상 기록을 보존한 채 종료 코드 1을 반환합니다.

수집값 해시는 내부 대조용입니다. 해시만으로 원천이나 시각의 진위를 보증하지 않습니다. 플랫폼에 별도 날짜·해시·과제 버전을 제출하지 않습니다. 공개 JSON과 Git 이력으로 내용을 검토할 수 있습니다.
